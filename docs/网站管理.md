# 网站管理手册

## 日常发布

```bash
cd "/home/ar/Personal Blogs/my-blog"
npm run dev -- --host 0.0.0.0 --background
```

写完文章后：

```bash
npm run check
npm run build
git diff --check
git status
git add .
git commit -m "Publish: 文章标题"
git push origin main
```

在 GitHub 仓库的 `Actions` 页面查看 `Deploy Astro site to Pages`。绿色对勾表示发布成功。

## 修改已发布文章

直接编辑原来的 Markdown 文件。建议填写更新时间：

```yaml
updatedDate: "2026-09-18T10:00:00+08:00"
```

不要随意重命名文件。文件名决定文章网址，重命名会使旧链接失效。

## 撤下文章

先在文章头部加入：

```yaml
draft: true
```

提交并推送后，该文章会从首页、文章列表、归档、RSS 和文章地址中移除，但源文件仍然保留。这样比直接删除更容易恢复。

## 管理分类

分类来自每篇文章的 `category`。同名分类会自动汇总，不需要另外维护分类文件。

建议保持少而稳定，例如：

- `创作设定`
- `开发笔记`
- `随笔`

修改分类后，首页统计、文章筛选和归档会在下次构建时自动更新。

## 更新依赖

平时不需要频繁升级。需要更新时先建立一个单独提交：

```bash
npm outdated
npm update
npm run check
npm run build
```

确认网站正常后再提交 `package.json` 和 `package-lock.json`。

## 使用 Git 恢复

查看最近提交：

```bash
git log --oneline -10
```

查看尚未提交的修改：

```bash
git diff
```

恢复某个文件到最近一次提交前，先确认该文件中没有需要保留的内容，然后执行：

```bash
git restore -- path/to/file
```

如果错误修改已经推送，优先使用 `git revert 提交编号` 创建一个反向提交，不要强制改写线上历史。

## 常见问题

### 本地页面打不开

```bash
npm run astro -- dev status
npm run astro -- dev logs
```

如果服务没有运行，重新执行开发命令。博客位于子路径，正确的本地地址是：

```text
http://localhost:4321/ARTEAAA.github.io/
```

### 推送后线上没有变化

1. 先确认 `git push` 成功。
2. 查看 GitHub Actions 是否完成。
3. 打开正确地址：`https://arteaaaa.github.io/ARTEAAA.github.io/`。
4. 使用 `Ctrl + F5` 强制刷新浏览器缓存。

### 构建失败

先运行：

```bash
npm run check
npm run build
```

错误通常会指出文件名和行号。文章最常见的问题是头部缺少引号、日期格式错误，或 `---` 没有成对出现。

### GitHub 要求重新登录

```bash
gh auth login
gh auth setup-git
```

这里登录的是 GitHub 账号，而不是 WSL 用户 `ar` 的系统密码。
